¿Por qué este tema es tan importante?

Hasta la Unidad 06, todas nuestras estructuras tenían un tamaño fijo decidido antes de compilar. Si creábamos un vector de 100 elementos, ese tamaño quedaba grabado en piedra.

En los programas reales (juegos, sistemas escolares, tiendas online), nunca sabemos de antemano cuántos datos ingresará el usuario. La memoria dinámica nos da el poder de crear vectores a medida mientras el programa está funcionando.

La Gran Avenida de Casilleros Numerados

Imaginá la Memoria RAM de tu computadora como una larguísima calle llena de millones de pequeños casilleros o buzones, uno al lado del otro. Cada casillero guarda 1 byte y tiene un número de puerta único.

1. El Casillero

Es el espacio físico en la memoria RAM donde se guardan los unos y ceros de nuestros datos.

2. El Contenido (Valor)

Es el dato que guardamos adentro del casillero (por ejemplo, el número 16 o la letra 'A').

3. El Número de Puerta

Se llama dirección de memoria (ej. 0x1004) e identifica exactamente dónde está ese casillero.

03 ¿Qué Pasa Cuando Creamos una Variable?

Cuando escribimos int edad = 16; en nuestro programa, el lenguaje C hace un trabajo automático por nosotros: busca un casillero libre en la RAM y asocia tres elementos:

Dirección: 0x1000
edad int (4 bytes)
16
1
Nombre (Etiqueta para humanos): edad. Nos permite usar la variable fácilmente sin memorizar números raros.
2
Valor (El dato guardado): 16. Es el número entero que está almacenado adentro de la caja.
3
Dirección de memoria (Ubicación en RAM): 0x1000. Es la coordenada real que usa el procesador para encontrar la caja.

🔑 Idea clave: Mientras usamos variables comunes o vectores estáticos, nos manejamos con el nombre. Pero en la memoria dinámica, los bloques que pedimos no tienen nombre propio: ¡solo tienen su dirección de memoria!

04 El Problema de los Vectores Estáticos

Recordemos cómo declarábamos un vector hasta ahora

Hasta ahora, cuando creábamos un vector común (estático), teníamos que decidir su tamaño antes de ejecutar el programa, en el momento de escribir el código:

vector_fijo.c Memoria Estática
// Tenemos que poner un número fijo sí o sí al programar: int numeros[100];

¿Qué pasa internamente?

Apenas arranca el programa, se reservan exactamente 100 casilleros fijos en la memoria. Ese tamaño no se puede achicar ni agrandar mientras el programa está corriendo.

¿Cuál es el problema real?

Muchas veces no sabemos cuántos datos vamos a necesitar hasta que el usuario se sienta frente a la pantalla y ejecuta el programa.

06 ¿Qué es entonces la Memoria Dinámica?

Definición Clara (Apunte Teórico)

La memoria dinámica es la capacidad de pedirle memoria al sistema operativo mientras el programa se está ejecutando (en tiempo de ejecución), reservando exactamente la cantidad de espacio que necesitamos en ese momento.

1
Primero preguntamos: El programa arranca y le pregunta al usuario: "¿Cuántos datos querés cargar hoy?".
2
El usuario responde: Por ejemplo, ingresa 20 por teclado con scanf.
3
Pedimos a medida: Recién en ese instante, nuestro programa le pide a la memoria RAM espacio exacto para 20 enteros. ¡No sobra ni falta ni un solo lugar!
4
Devolvemos al terminar: Cuando terminamos de usar esos datos, liberamos la memoria para que la computadora pueda reutilizarla.

08 Memoria Estática vs Memoria Dinámica

Memoria Estática (lo que ya conocíamos)

int numeros[10];
  • El tamaño (10) se define al escribir el programa.
  • No puede cambiar durante la ejecución del programa.
  • La memoria se reserva y se libera automáticamente sin que hagamos nada.

Memoria Dinámica (lo que aprendemos ahora)

int *numeros;
  • El tamaño se decide mientras el programa se ejecuta.
  • Se puede redimensionar (agrandar o achicar) si hace falta.
  • La memoria se reserva y se libera manualmente por el programador.

👀 Observá la diferencia en el código: En lugar de escribir corchetes fijos int numeros[10];, escribimos un asterisco int *numeros;. Enseguida vamos a descubrir qué significa ese asterisco.

09 Cuadro Comparativo Resumen

Característica Memoria Estática (int v[10];) Memoria Dinámica (int *v;)
¿Cuándo se decide el tamaño? Al escribir el código (antes de ejecutar). Mientras el programa corre (tiempo de ejecución).
¿Puede cambiar su tamaño? No, es 100% fijo de principio a fin. Sí, se puede ajustar con realloc().
¿Dónde se guarda en la RAM? En el Stack (Pila). En el Heap (Montículo / Depósito libre).
¿Quién reserva el espacio? El compilador automáticamente. El programador usando malloc() o calloc().
¿Quién libera el espacio? Se destruye sola al terminar la función. El programador usando free().

10 ¿Dónde se Guarda cada una? Stack vs Heap

La memoria RAM que usa nuestro programa está dividida en distintas zonas de trabajo. Las dos zonas fundamentales que tenés que conocer son el Stack y el Heap:

📦 Zona 1: El Stack (Pila)

Donde viven las variables comunes y vectores estáticos

  • Aquí se crean int edad; y int notas[10];.
  • Es totalmente automática y muy ordenada.
  • Tiene un tamaño limitado y rígido.
  • También guarda las variables puntero (ej. int *numeros;).

🏗️ Zona 2: El Heap (Montículo)

Donde se reserva toda la Memoria Dinámica

  • Es el gran depósito libre de la memoria RAM.
  • Tiene muchísimo espacio disponible a pedido.
  • Podemos pedir bloques de cualquier tamaño en vivo.
  • Queda reservado hasta que lo liberemos manualmente.

11 Entendiendo el Stack (La Pila Automática)

¿Por qué es tan cómodo pero limitado?

En el Stack, cada vez que empieza una función (como main), C apila prolijamente todas las variables que declaraste con su nombre y tamaño fijo.

Como todo está encajado uno arriba del otro como una pila de cajas, ninguna caja del medio puede estirarse sin chocar con las demás. Por eso en el Stack los tamaños tienen que ser fijos.

Stack • 0x1008
int cantidad = 5
Stack • 0x1004
float promedio = 8.5
Stack • 0x1000
int edad = 16

12 Entendiendo el Heap (El Gran Depósito Libre)

Un galpón gigante sin etiquetas de nombres

El Heap es una zona inmensa de la RAM donde hay espacio de sobra para pedir 10, 500 o 10.000 casilleros seguidos en cualquier momento. Pero tiene una particularidad muy importante:

1. En el Heap las cajas NO tienen nombre

Como los bloques en el Heap se crean mientras el programa ya está corriendo, no tienen un nombre de variable propio escrito en el código. Solo tienen su dirección de memoria (por ejemplo, "el bloque que empieza en la puerta 0x5000").

2. ¿Cómo llegamos entonces al Heap?

Cuando le pedimos un bloque de memoria al Heap, el sistema nos responde: "Listo, te reservé el espacio a partir de la dirección 0x5000". Nosotros guardamos esa dirección en un puntero en el Stack.

13 ¿Qué es Exactamente una Dirección de Memoria?

Toda celda de la memoria RAM tiene un número que indica su posición exacta, empezando desde el byte 0 hasta varios miles de millones.

Para que esos números largos sean más cortos y cómodos de leer, las computadoras los escriben en notación hexadecimal, que siempre empieza con el prefijo 0x:

  • 0x1000, 0x1004, 0x1008 (como los números de una cuadra).
  • No tenés que hacer cuentas con ellos: solo pensalos como el código postal o número de puerta de una casilla en la RAM.

¿Por qué avanzan de 4 en 4 en un int?

Dirección: 0x5000 (ocupa 5000 a 5003)
Primer int: 10
Dirección: 0x5004 (ocupa 5004 a 5007)
Segundo int: 20
Dirección: 0x5008 (ocupa 5008 a 5011)
Tercer int: 30

Como cada int ocupa 4 bytes, cada entero empieza 4 casilleros después del anterior.

14 ¡Ya Usabas Direcciones de Memoria con scanf!

El misterio del símbolo & (Ampersand) develado

Desde tu primera clase de programación en C, cada vez que leías un número por teclado escribías un símbolo & adelante de la variable. ¿Por qué era obligatorio?

repaso_scanf.c El operador &
int edad; printf("Ingrese su edad: "); scanf("%d", &edad); // &edad significa: "la dirección de memoria de edad"

edad (sin el &)

Significa el valor guardado adentro de la caja (por ejemplo, 16). Eso es lo que necesita printf("%d", edad); para mostrarlo en pantalla.

&edad (con el &)

Significa la dirección de memoria donde vive la caja (por ejemplo, 0x1000). scanf necesita la dirección de la casa para poder ir hasta ahí y guardar el dato que escribió el usuario.

15 ¿Qué es un Puntero? (Explicado desde Cero)

El puente entre nuestro programa y el Heap

Un puntero es simplemente una variable que, en lugar de guardar un número común (como 16) o una letra (como 'A'), guarda una dirección de memoria (como 0x5000).

Variable int común

int cantidad = 5;
Guarda un número entero directamente adentro de su caja.

Variable float común

float nota = 8.5;
Guarda un número con coma directamente adentro de su caja.

Variable Puntero int *

int *numeros;
Guarda la dirección de memoria donde están los números enteros.

💡 ¿Por qué se llama "puntero"? Porque al tener anotada la dirección de otro lugar de la RAM, actúa como una flecha que apunta hacia ese lugar.

16 La Analogía del Papelito con la Dirección

El Depósito vs El Papelito

Imaginá que alquilás un depósito grande en las afueras de la ciudad (en el Heap) para guardar mercadería.

El depósito no entra en tu bolsillo. Lo que vos llevás en tu bolsillo (en el Stack) es un papelito donde anotaste la dirección del depósito: "Av. Memoria 0x5000".

  • El papelito = tu variable puntero (int *vector).
  • El depósito real = el bloque de memoria en el Heap.
  • Mirando el papelito, podés ir al depósito cuantas veces quieras a guardar o leer datos.

17 ¿Cómo se Declara un Puntero en C?

Tal como muestra el apunte en las páginas 28 y 29, para declarar un puntero escribimos el tipo de dato al que va a apuntar, seguido de un asterisco * y el nombre de la variable:

declaracion_punteros.c Sintaxis en C
int *numeros; // Puntero que apuntará a números enteros (int) int *vector; // Otro puntero a enteros (muy usado en el apunte) float *precios; // Puntero que apuntará a números con coma (float) char *letras; // Puntero que apuntará a caracteres (char)

¿Qué significa el * en int *vector;?

El asterisco en la declaración le avisa al compilador: "Atención: vector no es un entero común, es una variable que guarda la dirección de memoria donde empiezan uno o varios enteros".

¿Por qué hay que indicar el tipo (int, float)?

Porque aunque todas las direcciones son números de puerta, C necesita saber qué tipo de dato vive en esa puerta y cuántos bytes ocupa cada casillero cuando avancemos al siguiente.

19 Los Dos Usos del Asterisco *

A los principiantes suele confundirles ver el asterisco * en dos momentos distintos. Es muy fácil si distinguís cuándo estás creando el puntero y cuándo lo estás usando para viajar a la celda:

Uso 1: En la Declaración

int *p; ➔ Crear la variable puntero

Cuando tiene el tipo int adelante, solo estamos creando la variable que guardará direcciones.

int *p; // Crea el puntero 'p' p = &x; // Sin *: guarda la dirección
Uso 2: Seguir la Flecha

*p = 25; ➔ Ir al casillero apuntado

Cuando escribimos *p en una instrucción, significa: "seguí la flecha de p y accedé al dato que está en ese destino".

*p = 25; // Viaja a 'x' y guarda 25 printf("%d", *p); // Muestra 25

21 El Valor Especial NULL ("No Apunta a Nada")

❌ Puntero sin inicializar (Peligroso)

Si declarás int *vector; suelto y todavía no le asignaste una dirección válida, adentro tiene basura aleatoria (una dirección cualquiera de la RAM).

int *vector
??? (Dirección Basura)
✅ Puntero inicializado en NULL

NULL es un valor especial de C que significa "este puntero está vacío y no apunta a ningún lugar todavía" (o que falló la reserva de memoria).

int *vector = NULL
NULL (0x0)

🛡️ Buena costumbre desde hoy: Si declarás un puntero y no le vas a asignar memoria en esa misma línea, inicializalo en int *vector = NULL;.

22 Las 4 Funciones de la Memoria Dinámica

En la página 29 del apunte se presentan las 4 herramientas fundamentales que nos brinda la biblioteca <stdlib.h> para controlar la memoria dinámica en C:

1. malloc() • Unidad 08

Reservar memoria

Pide un bloque de memoria de un tamaño determinado en el Heap y nos devuelve la dirección donde empieza.

2. free() • Unidad 08

Liberar memoria

Devuelve al sistema operativo la memoria que habíamos reservado cuando ya terminamos de usarla.

3. calloc() • Unidad 09

Reservar memoria inicializada en 0

Reserva memoria para un vector en el Heap y además limpia todas sus casillas dejándolas en 0 automáticamente.

4. realloc() • Unidad 09

Cambiar el tamaño de la memoria

Permite agrandar o achicar un bloque de memoria dinámica que ya teníamos reservado sin perder los datos cargados.

23 Las 4 Etapas de Todo Programa con Memoria Dinámica

Siempre que trabajemos con memoria dinámica en las próximas clases, vamos a respetar este orden lógico de 4 pasos:

1
Declarar el puntero: Creamos la variable puntero que guardará la dirección (ej. int *vector;) y averiguamos cuántos datos quiere el usuario (cantidad).
2
Reservar en el Heap: Pedimos el bloque exacto de memoria con malloc() o calloc() y verificamos que no sea NULL.
3
Usar el vector normalmente: Cargamos datos con scanf, recorremos con for, buscamos o mostramos usando vector[i].
4
Liberar la memoria: Antes de terminar el programa, devolvemos el bloque al Heap con free(vector);.

24 ¿Qué Pasa si Administramos Mal la Memoria Dinámica?

Con gran poder viene una gran responsabilidad

Como en el Heap la memoria no se maneja sola, hay dos situaciones críticas que un buen programador siempre debe evitar:

1. Olvidarse de liberar (Fuga de Memoria)

Si pedís memoria en el Heap y nunca la liberás con free(), ese espacio queda ocupado e inutilizable mientras el programa siga abierto. En programas largos o juegos, esto va llenando la RAM hasta trabar la computadora.

2. Perder la dirección del papelito

El puntero es el único mapa que sabe dónde está nuestro bloque en el Heap. Si borramos o cambiamos la dirección guardada en el puntero antes de liberar el bloque, nunca más podremos acceder a esos datos ni liberarlos.

29 Los 3 Errores Conceptuales más Frecuentes

❌ Error 1: Creer que int *v; ya creó un vector

Escribir int *vector; solo crea el papelito vacío (el puntero), pero todavía no reservó ningún casillero en el Heap. Si hacés vector[0] = 5; sin pedir memoria antes, el programa falla.

❌ Error 2: Confundir p con *p

Recordá siempre: p (sin asterisco) es la dirección de la puerta. En cambio, *p (con asterisco) o p[0] es el dato guardado adentro de esa puerta.

❌ Error 3: Guardar un número suelto en un puntero

Hacer int *p = 15; está mal porque 15 no es una dirección de memoria válida. Un puntero solo debe recibir una dirección (con &, con malloc) o NULL.

31 Ejercicio de Razonamiento 2: ¿Estática o Dinámica?

Para cada una de estas tres situaciones, decidí si conviene usar un vector estático o memoria dinámica y por qué:

Situación A

Guardar las recaudaciones de los 12 meses del año de un comercio.

Situación B

Cargar los precios de los productos de un carrito de compras cuya cantidad ingresa el cliente.

Situación C

Un sistema donde un club agrega socios nuevos todos los días sin límite fijo.

🔍 Ver solución justificada
  • Situación A ➔ Memoria Estática (float meses[12];): El año siempre tiene exactamente 12 meses. El tamaño se conoce antes de ejecutar y nunca cambia.
  • Situación B ➔ Memoria Dinámica (float *precios;): No sabemos si el cliente comprará 2 productos o 150 hasta que usa el programa.
  • Situación C ➔ Memoria Dinámica (Socio *socios;): La cantidad crece durante el uso del programa y necesitamos pedir y redimensionar la memoria en el Heap.

32 Ejercicio de Razonamiento 3: Detectá el Error

Un estudiante quiso crear su primer vector con punteros y escribió este código, pero al ejecutarlo el programa se cierra con un error grave. ¿Por qué falla?

codigo_con_error.c ¿Qué falta acá?
#include <stdio.h> int main() { int *numeros; numeros[0] = 100; printf("%d\n", numeros[0]); return 0; }
🔍 Ver diagnóstico del error

Diagnóstico: La línea int *numeros; únicamente declara el puntero (el papelito), pero nunca se reservó memoria en el Heap (falta llamar a malloc). Como numeros no fue inicializado, contiene una dirección basura aleatoria, y al intentar escribir numeros[0] = 100; el programa intenta pisar una zona prohibida de la RAM. En la Unidad 08 aprenderemos a reservar ese espacio con malloc().

33 Resumen de la Unidad 07 y Próximo Paso

Conceptos Clave del Apunte

  • Memoria Estática (int numeros[10];): Tamaño fijo al programar, vive en el Stack, se gestiona sola.
  • Memoria Dinámica (int *numeros;): Tamaño decidido al ejecutar (como pedir las sillas cuando llegan los invitados a la fiesta).
  • Heap: La zona de la RAM donde se guarda la memoria dinámica.
  • Puntero (*): Variable que guarda la dirección de memoria donde empieza nuestro bloque en el Heap.
  • Las 4 funciones de <stdlib.h>: malloc(), free(), calloc() y realloc().
