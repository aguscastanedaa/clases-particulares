01 39. ¿Por Qué Es el Ejercicio Más Integrador del Apunte?

Destacado del Apunte (Sección 39, págs. 36–37)

"Este es prácticamente el ejercicio más integrador del primer PDF." Porque para resolver una transferencia bancaria real necesitamos unir en una sola función 8 herramientas fundamentales del lenguaje C.

Las 8 piezas que junta este ejercicio

  • 1. Structs: para modelar cada cuenta bancaria.
  • 2. Punteros: para modificar dos cuentas a la vez.
  • 3. Operador ->: para acceder a los campos apuntados.
  • 4. Condicionales if: para verificar reglas antes de mover plata.

Y además...

  • 5. Operadores lógicos (&&, ||): para combinar requisitos.
  • 6. Comparación (==, >=, <): para chequear estado y saldo.
  • 7. Modificación (-=, +=): para restar y sumar el monto.
  • 8. return: devuelve 1 (éxito) o 0 (error).

02 El Problema: ¿Qué Ocurre Cuando Hacés una Transferencia?

Pensá en cuando abrís una billetera virtual o aplicación del banco en tu celular y le transferís $3000 a un amigo:

Cuenta Origen (Tu cuenta)

saldo = $10000
↓
transferir $3000 (-$3000)
↓
saldo = $7000

Cuenta Destino (Tu amigo)

saldo = $5000
↓
recibe $3000 (+$3000)
↓
saldo = $8000

🤔 Pregunta clave: ¿El dinero se crea o se destruye? ¡No! La suma total antes ($\$10000 + \$5000 = \$15000$) debe ser exactamente igual a la suma total después ($\$7000 + \$8000 = \$15000$).

03 Paso 1: Modelar struct CuentaBancaria

Miremos la estructura exacta definida en la página 36 del apunte:

cuenta_bancaria.c Sección 39 del Apunte
struct CuentaBancaria { int numero; float saldo; int estado; };

¿Qué representa cada campo?

  • int numero; → El número único que identifica a la cuenta (ej: 101, 102).
  • float saldo; → Cuánta plata tiene disponible actualmente (ej: 10000.0).
  • int estado; → Indica si la cuenta está habilitada para operar:
    • estado = 1 → activa (puede enviar y recibir)
    • estado = 0 → inactiva (bloqueada o cerrada)

04 Entendiendo el Campo estado (1 = Activa, 0 = Inactiva)

En sistemas reales, cuando una cuenta se suspende o se bloquea por seguridad, no se borra de la memoria sino que se cambia su campo estado de 1 a 0:

Cuenta Activa (Puede operar)
.numero
101
.saldo
10000.00
.estado
1 (Activa)
Cuenta Inactiva (Bloqueada)
.numero
102
.saldo
5000.00
.estado
0 (Inactiva)

💡 Una cuenta con estado == 0 no puede enviar dinero ni tampoco recibir dinero. Cualquier intento de transferencia que involucre una cuenta inactiva debe rechazarse.

05 Paso 2: ¿Por Qué transferir Necesita Recibir Punteros?

Explicación del Apunte (Página 36)

La función recibe struct CuentaBancaria *origen y struct CuentaBancaria *destino porque necesitamos modificar los saldos originales de ambas cuentas en main.

❌ Si recibiera las Structs por valor (sin *)
int transferirMal(struct CuentaBancaria origen, struct CuentaBancaria destino, float monto) { origen.saldo -= monto; destino.saldo += monto; return 1; }

Modifica dos copias temporales que se destruyen al terminar la función. En main las cuentas siguen en $10000 y $5000.

✅ Recibiendo punteros (*origen y *destino)
int transferir(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float monto) { origen->saldo -= monto; destino->saldo += monto; return 1; }

Con *origen y *destino apuntamos a las variables reales de main y modificamos sus saldos con ->.

06 Cómo Apuntan origen y destino en Memoria RAM

Cuando desde main llamamos a transferir(&cuenta1, &cuenta2, 3000);, ocurre esto en la memoria RAM:

En transferir(): Puntero origen
Guarda: 0x1000 (&cuenta1)
↓ apunta con origen->saldo a ↓
cuenta1 en main (0x1000)
$10000 ➔ $7000
En transferir(): Puntero destino
Guarda: 0x2000 (&cuenta2)
↓ apunta con destino->saldo a ↓
cuenta2 en main (0x2000)
$5000 ➔ $8000

📌 Además, recordá la Sección 23 del apunte: un return solo puede devolver un valor (usaremos return 1 o return 0 para informar si salió bien), mientras que las dos cuentas se actualizan por referencia mediante los punteros.

07 Ejemplo Nivel 1: Depositar en una Sola Cuenta con Puntero

Antes de juntar dos cuentas, calentemos motores modificando una sola cuenta mediante un puntero si está activa:

nivel1_depositar.c Nivel 1
#include <stdio.h> struct CuentaBancaria { int numero; float saldo; int estado; }; int depositar(struct CuentaBancaria *cta, float monto) { if(cta->estado == 1 && monto > 0) { cta->saldo += monto; return 1; } return 0; } int main() { struct CuentaBancaria miCuenta = {101, 5000.0, 1}; depositar(&miCuenta, 2000.0); printf("Nuevo saldo: %.2f\n", miCuenta.saldo); return 0; }

¿Qué hicimos acá?

  • Mandamos la dirección &miCuenta.
  • Adentro de depositar chequeamos que la cuenta esté activa (cta->estado == 1) y el monto sea positivo.
  • Sumamos al saldo con cta->saldo += monto; y devolvemos 1.
Salida bash
Nuevo saldo: 7000.00

08 Paso 3: ¿Qué Debemos Comprobar Antes de Transferir?

Las Preguntas del Apunte (Página 36)

Antes de restar o sumar un solo peso, el apunte nos marca el orden lógico de comprobaciones que debemos hacer:

1
Primero: ¿Origen activa?
Comprobamos si origen->estado == 1 (si vale 0, la cuenta que quiere mandar plata está inactiva).
2
Después: ¿Destino activa?
Comprobamos si destino->estado == 1 (si vale 0, la cuenta receptora está inactiva y no puede recibir plata).
3
Después: ¿Origen tiene suficiente saldo? (y monto positivo)
Comprobamos si origen->saldo >= monto (y monto > 0). No podemos transferir $3000 si en la cuenta solo hay $1500.

09 Regla de Oro Bancaria: Si Algo Falla, No Modificamos Nada

En la página 37 del apunte dice: "Si algo falla: return 0; Y no modificamos nada." En informática bancaria esto se llama atomicidad (la operación se hace entera o no se hace nada). Mirá qué grave sería descontar antes de validar:

❌ Peligro Mortal: Restar antes de validar destino
if(origen->estado == 1 && origen->saldo >= monto) { origen->saldo -= monto; // ¡Ya le sacó la plata! if(destino->estado == 1) { destino->saldo += monto; return 1; } } return 0;

Si destino estaba inactiva, a origen ya le restaste $3000 y a destino no se los sumaste. ¡Desaparecieron $3000 del sistema!

✅ Correcto: Validar TODO antes de tocar los saldos
// 1° Verificamos TODAS las condiciones: if(origen->estado != 1) return 0; if(destino->estado != 1) return 0; if(monto <= 0 || origen->saldo < monto) return 0; // 2° Recién acá tocamos ambos saldos juntos: origen->saldo -= monto; destino->saldo += monto; return 1;

Si cualquier validación falla, la función sale con return 0; sin haber tocado ni un centavo.

10 Paso 4: Actualización de Saldos y return 1 / return 0

Si todo está bien (Págs. 36–37)

origen->saldo -= monto; destino->saldo += monto; return 1;

• origen->saldo -= monto; equivale a origen->saldo = origen->saldo - monto;.
• destino->saldo += monto; equivale a destino->saldo = destino->saldo + monto;.
• Nota: en el esquema conceptual de la pág. 36 aparece escrito como idea origen.saldo -= monto, pero en código C usamos la flecha -> porque origen y destino son punteros.

Si algo falla

return 0;

• Devolver 0 significa Falso / Operación rechazada.
• Devolver 1 significa Verdadero / Operación realizada con éxito.
• Así, quien llamó a transferir(...) desde main puede usar un if para mostrar un mensaje al usuario.

11 Dos Formas Equivalentes de Escribir transferir

Tanto en clase como en el examen podés escribir las validaciones paso a paso o en un solo if con &&. Ambas son 100% válidas:

Forma A: Paso a paso (Guard clauses) Muy clara
int transferir(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float monto) { if(origen->estado != 1) { return 0; } if(destino->estado != 1) { return 0; } if(monto <= 0 || origen->saldo < monto) { return 0; } origen->saldo -= monto; destino->saldo += monto; return 1; }
Forma B: Con operador lógico && Compacta
int transferir(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float monto) { if(origen->estado == 1 && destino->estado == 1 && monto > 0 && origen->saldo >= monto) { origen->saldo -= monto; destino->saldo += monto; return 1; } return 0; }

12 Ejemplo Nivel 2: Programa Completo ($10000 ➔ $7000 y $5000 ➔ $8000)

transferencia_apunte.c Nivel 2
#include <stdio.h> struct CuentaBancaria { int numero; float saldo; int estado; }; int transferir(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float monto) { if(origen->estado != 1) return 0; if(destino->estado != 1) return 0; if(monto <= 0 || origen->saldo < monto) return 0; origen->saldo -= monto; destino->saldo += monto; return 1; } int main() { struct CuentaBancaria origen = {101, 10000.0, 1}; struct CuentaBancaria destino = {102, 5000.0, 1}; int ok = transferir(&origen, &destino, 3000.0); if(ok == 1) { printf("Origen: $%.2f | Destino: $%.2f\n", origen.saldo, destino.saldo); } return 0; }
Paso Chequeo / Acción origen.saldo destino.saldo

Probemos mentalmente 4 llamadas distintas a transferir(&c1, &c2, monto) y veamos en qué línea termina cada una:

14 Validación Defensiva Extra: ¿Y Si Se Transfiere a Sí Misma?

¿Qué pasa si alguien llama por error a transferir(&cta1, &cta1, 3000) pasando dos veces la misma cuenta?

misma_cuenta.c Chequeo extra
// Si ambos punteros apuntan a la misma dirección // o tienen el mismo número de cuenta: if(origen == destino || origen->numero == destino->numero) { return 0; // No tiene sentido transferirse a sí mismo }

¿Qué compara origen == destino?

Como origen y destino son punteros, origen == destino compara si ambos guardan la misma dirección de memoria RAM. Y origen->numero == destino->numero verifica si tienen el mismo número de cuenta.

15 Variante: Informar Por Qué Falló la Transferencia

El apunte pide devolver 1 si salió bien y 0 si algo falla. ¿Y si en un sistema real quisiéramos saber exactamente cuál fue la causa del rechazo? Podemos usar códigos negativos:

codigos_retorno.c Diagnóstico
int transferirDetallado(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float monto) { if(origen->estado != 1) return -1; if(destino->estado != 1) return -2; if(monto <= 0) return -3; if(origen->saldo < monto) return -4; origen->saldo -= monto; destino->saldo += monto; return 1; }

Tabla de códigos

  • 1 → Transferencia exitosa.
  • -1 → Error: Cuenta origen inactiva.
  • -2 → Error: Cuenta destino inactiva.
  • -3 → Error: Monto inválido (menor o igual a 0).
  • -4 → Error: Saldo insuficiente en origen.

⚠️ Nota para el examen: Si la consigna pide devolver 1 o 0 como en el apunte, usá siempre return 1; y return 0;.

16 Ejemplo Nivel 3: Ampliar la Cuenta con el Nombre del Titular

Agreguemos ahora un campo char titular[50]; a struct CuentaBancaria y una función mostrarCuenta para imprimir el estado antes y después de transferir:

cuenta_con_titular.c Nivel 3
#include <stdio.h> struct CuentaBancaria { int numero; char titular[50]; float saldo; int estado; }; void mostrarCuenta(struct CuentaBancaria c) { printf("Cta #%d (%s) | Saldo: $%.2f | Est: %d\n", c.numero, c.titular, c.saldo, c.estado); } int transferir(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float monto) { if(origen->estado == 1 && destino->estado == 1 && monto > 0 && origen->saldo >= monto) { origen->saldo -= monto; destino->saldo += monto; return 1; } return 0; } int main() { struct CuentaBancaria c1 = {101, "Ana", 10000.0, 1}; struct CuentaBancaria c2 = {102, "Bruno", 5000.0, 1}; transferir(&c1, &c2, 3000.0); mostrarCuenta(c1); mostrarCuenta(c2); return 0; }

Por valor vs Por puntero en el mismo programa

• mostrarCuenta(c1) recibe la estructura por valor (con punto c.saldo) porque solo necesita leerla e imprimirla.
• transferir(&c1, &c2, 3000.0) recibe punteros (con flecha origen->saldo) porque necesita modificar los saldos reales.

Salida bash
Cta #101 (Ana) | Saldo: $7000.00 | Est: 1 Cta #102 (Bruno) | Saldo: $8000.00 | Est: 1

17 Ejemplo Nivel 4: Combinando con Arreglos de Structs (El Banco)

En un banco real no tenemos dos variables sueltas c1 y c2, sino un arreglo de cuentas struct CuentaBancaria banco[100];. ¿Cómo transferimos si solo conocemos el numero de cuenta origen y el numero de cuenta destino?

1
Buscamos la posición de la cuenta origen: int idxOrigen = buscarCuenta(banco, tamano, numOrigen);
2
Buscamos la posición de la cuenta destino: int idxDestino = buscarCuenta(banco, tamano, numDestino);
3
Verificamos que ambas existan: Si idxOrigen != -1 && idxDestino != -1, llamamos a:
transferir(&banco[idxOrigen], &banco[idxDestino], monto);

18 Código Completo: Búsqueda en el Arreglo + transferir

banco_completo.c Nivel 4 Integrador
#include <stdio.h> struct CuentaBancaria { int numero; float saldo; int estado; }; int buscarCuenta(struct CuentaBancaria b[], int n, int num) { for(int i = 0; i < n; i++) { if(b[i].numero == num) return i; } return -1; } int transferir(struct CuentaBancaria *orig, struct CuentaBancaria *dest, float monto) { if(orig->estado == 1 && dest->estado == 1 && monto > 0 && orig->saldo >= monto) { orig->saldo -= monto; dest->saldo += monto; return 1; } return 0; } int main() { struct CuentaBancaria banco[3] = { {101, 10000.0, 1}, {205, 2000.0, 0}, {309, 5000.0, 1} }; int p1 = buscarCuenta(banco, 3, 101); int p2 = buscarCuenta(banco, 3, 309); if(p1 != -1 && p2 != -1) { transferir(&banco[p1], &banco[p2], 3000.0); } printf("101: $%.0f | 309: $%.0f\n", banco[0].saldo, banco[2].saldo); return 0; }

Analicemos &banco[p1]

1. buscarCuenta(banco, 3, 101) devuelve p1 = 0.
2. buscarCuenta(banco, 3, 309) devuelve p2 = 2.
3. &banco[0] es la dirección de memoria del casillero 0 del arreglo, y &banco[2] es la dirección del casillero 2.
4. ¡No tuvimos que cambiar ni una coma de la función transferir!

Salida bash
101: $7000 | 309: $8000

21 Errores Frecuentes de Principiantes (Parte 1)

Error #1: Usar el operador punto (.) en lugar de la flecha (->) dentro de transferir, u olvidar el & al llamar desde main.

❌ Incorrecto: Punto en puntero y llamada sin &
int transferir(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float m) { origen.saldo -= m; // Error: origen es puntero } // En main: transferir(cta1, cta2, 3000); // Falta &

El compilador rechaza origen.saldo porque un puntero requiere ->, y rechaza cta1 sin & porque espera una dirección.

✅ Correcto: Flecha -> adentro y & al llamar
int transferir(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float m) { origen->saldo -= m; destino->saldo += m; return 1; } // En main: transferir(&cta1, &cta2, 3000);

En main mandamos direcciones con & y en la función accedemos con ->.

22 Errores Frecuentes de Principiantes (Parte 2)

Error #2: Confundir comparación (==) con asignación (=) al verificar el estado de la cuenta, o usar > en vez de >= para el saldo.

❌ Incorrecto: = en el if y > estricto
// ¡Activa la cuenta a la fuerza en vez de preguntar! if(origen->estado = 1) { ... } // No deja transferir todo tu saldo ($10000 de $10000): if(origen->saldo > monto) { ... }

origen->estado = 1 le asigna 1 a una cuenta bloqueada y siempre da verdadero. Y si tenés $10000, tenés derecho a transferir los $10000 completos.

✅ Correcto: == 1 para estado y >= monto para saldo
if(origen->estado == 1 && destino->estado == 1 && origen->saldo >= monto) { ... }

Con == comparamos sin alterar el estado, y con >= permitimos transferir hasta el último peso disponible (quedando el saldo en 0.00).

23 Errores Frecuentes de Principiantes (Parte 3)

Error #3: Reemplazar el saldo con = en lugar de restar y sumar con -= y +=.

❌ Incorrecto: Sobrescribir el saldo con =
origen->saldo = monto; destino->saldo = monto;

Si ambas cuentas quedan con $3000, perdiste el saldo anterior que tenían ($10000 y $5000).

✅ Correcto: Restar con -= y sumar con +=
origen->saldo -= monto; destino->saldo += monto;

Descuenta monto de lo que ya tenía origen ($10000 - $3000 = $7000) y lo suma a lo que ya tenía destino ($5000 + $3000 = $8000).

26 Ejemplo Espejo: Compra entre Cliente y Producto

Mirá cómo el mismo razonamiento de transferir sirve incluso cuando los dos punteros apuntan a dos tipos de Structs distintos:

comprar_producto.c Dos Structs Distintas
#include <stdio.h> struct Cliente { char nombre[40]; float billetera; }; struct Producto { char nombre[40]; float precio; int stock; }; int comprar(struct Cliente *c, struct Producto *p, int cant) { float total = p->precio * cant; if(cant <= 0 || p->stock < cant || c->billetera < total) { return 0; } p->stock -= cant; c->billetera -= total; return 1; } int main() { struct Cliente cli = {"Ana", 5000.0}; struct Producto prod = {"Cuaderno", 1500.0, 10}; if(comprar(&cli, &prod, 2)) { printf("Saldo: $%.0f | Stock: %d\n", cli.billetera, prod.stock); } return 0; }

Misma estructura mental

  1. Calculamos el costo total = p->precio * cant.
  2. Validamos todo antes de modificar: cantidad positiva, stock suficiente y billetera suficiente.
  3. Si todo cumple, descontamos stock y billetera y devolvemos 1.
Salida bash
Saldo: $2000 | Stock: 8

27 Buenas Prácticas en Funciones de Modificación con Punteros

1. Validar primero, modificar al final

Colocá todos los chequeos de error al comienzo de la función. Solo cuando estés 100% seguro de que todas las condiciones se cumplen, ejecutá las líneas que alteran los campos apuntados.

2. Separar lógica de negocio e impresión

Fijate que en el apunte la función transferir no tiene ningún printf adentro: hace su trabajo en silencio y devuelve 1 o 0. Luego main() decide qué mensaje mostrar en pantalla.

28 El Algoritmo del Apunte en 5 Pasos Claros

1
Recibir punteros: struct CuentaBancaria *origen, struct CuentaBancaria *destino, float monto.
2
Comprobar cuenta origen: ¿origen->estado == 1? Si no, return 0;.
3
Comprobar cuenta destino: ¿destino->estado == 1? Si no, return 0;.
4
Comprobar monto y saldo: ¿monto > 0 y origen->saldo >= monto? Si no, return 0;.
5
Actualizar y confirmar: origen->saldo -= monto; destino->saldo += monto; return 1;.

struct CuentaBancaria a = {1, 4000.0, 1}; struct CuentaBancaria b = {2, 1000.0, 1}; int r1 = transferir(&a, &b, 2500.0); int r2 = transferir(&a, &b, 2000.0); printf("r1=%d r2=%d\n", r1, r2); printf("a=%.0f b=%.0f\n", a.saldo, b.saldo);

Seguimiento paso a paso

  • 1° llamada (2500.0): a tiene $4000 (alcanza). Se transfieren $2500 → a queda en $1500, b queda en $3500 y r1 = 1.
  • 2° llamada (2000.0): Ahora a solo tiene $1500. Como $1500 < $2000, falla la validación → no toca los saldos y r2 = 0.
  • Imprime: r1=1 r2=0 y a=1500 b=3500.

30 Ejercicio 1: Función extraer con Límite y Estado

Enunciado

Dada struct CuentaBancaria { int numero; float saldo; int estado; };, escribí una función int extraer(struct CuentaBancaria *cuenta, float monto) que verifique que la cuenta esté activa (1), que el monto sea mayor a 0 y que el saldo alcance. Si todo se cumple, resta el monto del saldo y retorna 1; si no, retorna 0.

💻 Ver solución paso a paso
int extraer(struct CuentaBancaria *cuenta, float monto) { if(cuenta->estado != 1) { return 0; } if(monto <= 0 || cuenta->saldo < monto) { return 0; } cuenta->saldo -= monto; return 1; }

31 Ejercicio 2: Transferencia con Comisión Bancaria del 2%

Enunciado

Escribí una variante int transferirConComision(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float monto) donde el banco le cobra a la cuenta origen una comisión del 2% adicional sobre el monto (es decir, origen debe tener saldo suficiente para cubrir monto * 1.02f, y a destino le llega exactamente monto).

💻 Ver solución paso a paso
int transferirConComision(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float monto) { float costoTotal = monto * 1.02f; if(origen->estado == 1 && destino->estado == 1 && monto > 0 && origen->saldo >= costoTotal) { origen->saldo -= costoTotal; destino->saldo += monto; return 1; } return 0; }

💡 Observá que validamos origen->saldo >= costoTotal para asegurarnos de que le alcance tanto para el monto como para el 2% de comisión.
