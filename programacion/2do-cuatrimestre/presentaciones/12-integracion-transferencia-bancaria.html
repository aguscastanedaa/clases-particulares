Integración: Transferencia Bancaria

El ejercicio maestro: structs, punteros, operador ->, lógica defensiva, validaciones atómicas e integridad transaccional en C.

struct CuentaBancaria Punteros *origen y *destino Validaciones de seguridad Integridad atómica (return 1 / 0)

💡 Guía de navegación: Usá la barra espaciadora o las flechas del teclado (→ / ←) para avanzar diapositiva por diapositiva.

01 Objetivos Pedagógicos

La culminación práctica del apunte

Este es el ejercicio integrador más completo de la materia. Conecta de manera armónica todos los conceptos aprendidos a lo largo del cuatrimestre.

Resolver una transferencia bancaria requiere rigor profesional: dos cuentas deben modificarse en RAM de forma simultánea, pero si una sola validación de negocio falla, el estado de ambas cuentas debe quedar intacto.

Lo que vas a dominar en esta clase

  • Modelar la entidad financiera struct CuentaBancaria.
  • Diseñar una función que recibe dos punteros a estructura simultáneos.
  • Implementar validaciones defensivas: monto positivo, cuentas activas y saldo.
  • Garantizar integridad transaccional (todo o nada).
  • Usar el valor de retorno (1 o 0) para informar éxito o fallo.

02 El Modelo: struct CuentaBancaria

Definición de la entidad bancaria con saldo y estado lógico.

cuenta.h Modelo
struct CuentaBancaria { int numero; float saldo; int estado; // 1 = activa, 0 = inactiva };

Significado de los Campos

  • numero: Identificador único de cuenta (ej. 1001, 2002).
  • saldo: Dinero disponible en la cuenta corriente.
  • estado: Bandera booleana (flag). Si vale 1, la cuenta puede operar; si vale 0, está bloqueada o inactiva y no puede enviar ni recibir transferencias.

03 Diagrama y Reglas de Negocio

Flujo Transaccional

Cuenta Origen ($10.000)
    ↓ debita $3.000
Nuevo saldo: $7.000

Cuenta Destino ($5.000)
    ↓ acredita $3.000
Nuevo saldo: $8.000

Protocolo de Validaciones Obligatorias

1
¿Monto positivo? (monto > 0).
2
¿Cuenta origen activa? (origen->estado == 1).
3
¿Cuenta destino activa? (destino->estado == 1).
4
¿Saldo suficiente? (origen->saldo >= monto).
5
¿Son cuentas distintas? (origen != destino).

04 Código de la Función: transferir

transferencia.c Lógica Defensiva
int transferir(struct CuentaBancaria *origen, struct CuentaBancaria *destino, float monto) { // Validaciones previas de seguridad: if (monto <= 0) { return 0; // Monto inválido } if (origen->estado != 1 || destino->estado != 1) { return 0; // Al menos una cuenta está inactiva } if (origen->saldo < monto) { return 0; // Saldo insuficiente } // Si todas las validaciones pasaron, ejecutamos la transacción atómica: origen->saldo -= monto; destino->saldo += monto; return 1; // Éxito total }

05 Simulación Completa en main()

simulacion.c Ejecución
int main(void) { struct CuentaBancaria cta1 = {101, 10000.0f, 1}; // Activa con $10.000 struct CuentaBancaria cta2 = {102, 5000.0f, 1}; // Activa con $5.000 printf("Antes: Cta1 = $%.2f | Cta2 = $%.2f\n", cta1.saldo, cta2.saldo); int exito = transferir(&cta1, &cta2, 3000.0f); if (exito) { printf("✅ Transferencia exitosa!\n"); } else { printf("❌ La transferencia fue rechazada.\n"); } printf("Despues: Cta1 = $%.2f | Cta2 = $%.2f\n", cta1.saldo, cta2.saldo); return 0; }
Terminal de salida bash
Antes: Cta1 = $10000.00 | Cta2 = $5000.00 ✅ Transferencia exitosa! Despues: Cta1 = $7000.00 | Cta2 = $8000.00

06 Resumen y Autoevaluación

Conceptos Integrados en este Ejercicio

  • Estructuras para empaquetar saldo, número y estado.
  • Punteros dobles para mutar dos entidades distintas.
  • Operador flecha -> para modificar saldos remotos.
  • Lógica booleana y condicionales para blindar la operación.
  • Retorno de estado numérico (1/0) como señal de éxito.

Checklist de Autoevaluación

✓ ¿Por qué es fundamental que la función reciba punteros y no structs por valor?
✓ ¿Qué pasaría si debitáramos antes de verificar si la cuenta destino está activa? (¡Fuga de dinero!).
✓ ¿Entiendo cómo se garantiza que ante un error ninguna cuenta se modifique?
