Punteros a Estructuras y el Operador Flecha (->)

Combinando structs y punteros: máxima eficiencia en el paso de parámetros, mutación directa de campos y la anatomía de ptr->campo vs (*ptr).campo.

struct *puntero Operador flecha -> (*emp).campo Aumento salarial porcentual

💡 Guía de navegación: Usá la barra espaciadora o las flechas del teclado (→ / ←) para avanzar diapositiva por diapositiva.

01 Objetivos Pedagógicos

¿Por qué necesitamos punteros a estructuras?

Una estructura puede ser inmensa (contener decenas de cadenas, vectores y números, pesando cientos de bytes). Pasarla por valor implica duplicar todos esos bytes en el Stack.

Pasar un puntero a una struct tiene dos ventajas determinantes: 1. Eficiencia extrema (solo viajan 8 bytes de dirección) y 2. Capacidad de modificar la entidad original de forma permanente.

Lo que vas a dominar en esta clase

  • Declarar y asignar punteros a estructuras: struct Empleado *emp.
  • Comprender la necesidad y origen del operador flecha ->.
  • Descifrar la equivalencia: emp->salario es (*emp).salario.
  • Entender la precedencia de operadores que obliga al paréntesis.
  • Implementar la función de aumento salarial del apunte oficial.

02 Declaración de un Puntero a Struct

Un puntero a struct guarda la dirección de memoria donde comienza la estructura.

empleado.c Puntero
struct Empleado { char nombre[50]; int edad; float salario; }; int main(void) { struct Empleado empleado; empleado.edad = 30; empleado.salario = 50000.0f; // Declaramos el puntero a la estructura: struct Empleado *ptr = &empleado; return 0; }

03 El Operador Flecha ->

La Regla Visual de Oro

Si tenés una variable struct directa, usás el punto: empleado.salario.
Si tenés un puntero a una struct, usás la flecha: emp->salario.

Variable ordinaria de Struct

empleado.salario

La variable contiene los datos directamente. Se usa el operador punto . para seleccionar el campo.

Puntero a una Struct

emp->salario

La variable contiene una dirección de memoria. La flecha -> viaja a esa dirección y accede al campo de la estructura remota.

04 ¿Por qué existe ->? La Trampa de Precedencia

El operador flecha emp->salario es una forma abreviada y elegante de escribir:

(*emp).salario

¿Por qué los paréntesis son obligatorios?

En C, el operador punto . tiene mayor prioridad de evaluación que el asterisco *.

Si escribís *emp.salario, C interpreta *(emp.salario), lo cual falla estrepitosamente porque emp no tiene un campo salario (es solo un puntero).

El rol pacificador de la flecha

Como escribir (*emp).campo en cada línea resultaba tedioso y propenso a errores tipográficos, los diseñadores de C introdujeron el operador -> para hacer ambas cosas en un solo paso: desreferenciar y acceder.

05 Ejemplo: Aumento Salarial Porcentual

Función que recibe un puntero a empleado y modifica su salario real en la memoria.

aumentar_salario.c Definición y Puntero
struct Empleado { char nombre[50]; int edad; float salario; }; void aumentarSalario(struct Empleado *emp, float porcentaje) { emp->salario += emp->salario * porcentaje / 100.0f; }
main.c Paso de Dirección &
int main(void) { struct Empleado emp = {"Carlos", 35, 100000.0f}; printf("Inicial: $%.2f\n", emp.salario); // Pasamos la dirección con & : aumentarSalario(&emp, 15.0f); printf("Con 15%%: $%.2f\n", emp.salario); return 0; }
Terminal de salida bash
Inicial: $100000.00 Con 15%: $115000.00

06 Resumen y Autoevaluación

Puntos Clave del Módulo

  • Pasar punteros a estructuras ahorra copias pesadas en memoria y permite modificar el original.
  • El operador -> se usa cuando accedemos a un campo a través de un puntero.
  • p->campo es 100% equivalente a (*p).campo.
  • En la llamada siempre debemos anteponer el operador &: funcion(&miStruct);.
