calloc() y realloc()

Memoria limpia inicializada a cero y redimensionamiento dinámico seguro en tiempo de ejecución

01 Objetivos de la Clase

Flexibilidad Total en Memoria

En la unidad anterior aprendimos a pedir un bloque de tamaño fijo con malloc(). Pero en el mundo real, los datos no siempre tienen un tamaño previsto y a veces necesitamos arrancar con valores limpios.

Hoy completamos las 4 funciones maestras de memoria dinámica en C: dominarás calloc() para tener memoria limpia y realloc() para agrandar o achicar arreglos dinámicos según haga falta.

Lo que vas a dominar hoy

  • Dominar el funcionamiento interno de realloc() y sus 3 posibles caminos en memoria.

02 La Trampa de la "Basura" en malloc()

¿Qué hay dentro de la memoria que te da malloc()?

malloc() sólo reserva las casillas en el Heap; no las limpia ni modifica sus bits. Queda exactamente lo que el programa anterior o el sistema operativo dejaron guardado ahí ("basura informática").

con_malloc.c
int *v = (int *)malloc(3 * sizeof(int)); // ¿Qué valor tiene v[0], v[1], v[2]? printf("%d %d %d\n", v[0], v[1], v[2]); // Salida impredecible: // -19284712 32766 0 <-- ¡Basura!
Estado en RAM tras malloc:
[0] -1928
[1] 32766
[2] 4501

⚠️ Si olvidás inicializar una posición e intentás acumular con suma += v[i], el resultado será una cifra disparatada.

03 La Solución: calloc()

Clear Allocation (o Contiguous Allocation)

calloc() reserva memoria para un arreglo de elementos en el Heap y escribe ceros (bytes en 0x00) en cada posición antes de entregártela.

Sintaxis de calloc()
void* calloc(size_t num_elementos, size_t tamano_cada_uno);
ejemplo_calloc.c
// Pide 3 enteros e inicializa a 0 int *v = (int *)calloc(3, sizeof(int)); printf("%d %d %d\n", v[0], v[1], v[2]); // Salida garantizada: // 0 0 0
Estado en RAM tras calloc:
[0] 0
[1] 0
[2] 0

✅ Todos los bits quedan en 0: para enteros es 0, para flotantes es 0.0 y para punteros es NULL.

04 Comparativa: malloc() vs calloc()

Característica malloc() calloc()
Argumentos 1 argumento: bytes totales (N * sizeof(T)) 2 argumentos: cantidad y tamaño (N, sizeof(T))
Contenido inicial Basura residual Garantizado todo en ceros (0x00)
Rendimiento Más rápido (sólo marca el bloque) Leve sobrecarga por escribir los ceros
¿Cuándo conviene? Si vas a sobreescribir todo inmediatamente (ej. scanf) Contadores, tablas de frecuencia, matrices vacías
Liberación Ambos se liberan exactamente igual: free(ptr); Ambos se liberan exactamente igual: free(ptr);

05 El Problema del Crecimiento Dinámico

¿Qué pasa si el vector se llena?

Imaginá que creaste un arreglo para 5 notas. El usuario sigue cargando notas y ahora necesita guardar 10.

❌
En vectores estáticos (int v[5];): Imposible. El tamaño está sellado en piedra y el programa colapsará si intentás escribir fuera de rango.
⚠️
Hacerlo a mano con malloc: Crear un vector nuevo de 10 elementos, copiar elemento por elemento con un bucle for, liberar el viejo con free() y cambiar el puntero... ¡Muy tedioso y propenso a errores!
✅
La solución de C: La función realloc() hace todo ese trabajo automáticamente en una sola línea.

06 La Función realloc() (Re-Allocation)

Cambiar el tamaño de un bloque en el Heap

Permite expandir o reducir un bloque de memoria previamente reservado con malloc() o calloc(), preservando intactos todos los datos previos.

Sintaxis de realloc()
void* realloc(void *puntero_existente, size_t nuevo_tamano_total_bytes);
1
puntero_existente: Puntero devuelto por malloc, calloc o un realloc previo (o NULL, en cuyo caso actúa exactamente como malloc).
2
nuevo_tamano_total_bytes: El nuevo tamaño TOTAL en bytes (por ejemplo: 10 * sizeof(int), NO la diferencia).

07 ¿Cómo Trabaja realloc() Tras Bambalinas?

Al pedir agrandar un bloque en el Heap pueden ocurrir tres escenarios:

A
Expansión en el lugar (In-Place): Si el espacio contiguo en la memoria está libre, simplemente corre el límite del bloque hacia la derecha. La dirección de memoria no cambia.
B
Reubicación automática: Si detrás de tu bloque hay datos de otra variable, el Heap busca un nuevo bloque libre más grande en otro lugar, copia automáticamente todos tus datos viejos, libera la memoria vieja y devuelve la nueva dirección.
C
Falla por falta de RAM: Si no hay memoria disponible, devuelve NULL y el bloque viejo se mantiene 100% intacto en su lugar original.

08 🚨 El Error Fatal de Principiante con realloc()

NUNCA hagas esto:

v = (int *)realloc(v, nuevo_tamano); // ☠️ ¡PELIGRO MORTAL!

¿Por qué es catastrófico?

Si el sistema operativo no tiene suficiente memoria libre para el nuevo tamaño, realloc() devuelve NULL.

Al asignar directamente v = NULL, perdiste la dirección de la memoria vieja. ¡No podés leer tus datos ni podés hacer free(v)! Causaste una fuga de memoria irrecuperable y perdiste todos tus datos previos.

✅ La Solución: Puntero Temporal

int *temp = (int *)realloc(v, nuevo_tam); if (temp == NULL) { printf("Error: memoria insuficiente\n"); // 'v' sigue sano con sus datos viejos } else { v = temp; // ¡Reasignación segura! }

09 Ejemplo Completo: Vector Auto-Expansible

vector_dinamico_crece.c
#include <stdio.h> #include <stdlib.h> int main(void) { int capacidad = 2; // Empezamos con espacio para sólo 2 elementos int cantidad = 0; int *vector = (int *)malloc(capacidad * sizeof(int)); if (vector == NULL) return 1; int numero; printf("Ingresá números enteros (-1 para terminar):\n"); while (scanf("%d", &numero) == 1 && numero != -1) { if (cantidad == capacidad) { // ¿Se llenó el vector? capacidad *= 2; // Estrategia: duplicar capacidad int *temp = (int *)realloc(vector, capacidad * sizeof(int)); if (temp == NULL) { printf("Error al reasignar memoria!\n"); free(vector); return 1; } vector = temp; printf(" [Vector expandido a %d lugares]\n", capacidad); } vector[cantidad++] = numero; } printf("\nIngresaste %d números en total:\n", cantidad); for (int i = 0; i < cantidad; i++) printf("%d ", vector[i]); printf("\n"); free(vector); vector = NULL; return 0; }

10 Reducir Memoria (Liberar lo que Sobra)

Ajustar al tamaño exacto

Imaginá que duplicaste capacidad hasta llegar a 1000 elementos, pero el usuario sólo ingresó 520. Las 480 posiciones sobrantes están ocupando memoria innecesaria en la máquina.

ajuste_exacto.c
// Reducir el vector a la cantidad exacta de elementos cargados int *temp = (int *)realloc(vector, cantidad * sizeof(int)); if (temp != NULL) { vector = temp; printf("Memoria optimizada a %d elementos exactos.\n", cantidad); }

💡 Nota importante: Al reducir un bloque con realloc(), el sistema operativo libera los bytes excedentes para que otros programas puedan utilizarlos, conservando intactos los primeros cantidad elementos.

12 Solución Desafío 1: Frecuencias con calloc()

solucion_frecuencias.c
#include <stdio.h> #include <stdlib.h> int main(void) { // calloc inicializa los 10 contadores en 0 automáticamente int *frecuencia = (int *)calloc(10, sizeof(int)); if (frecuencia == NULL) return 1; int num; printf("Ingresá dígitos del 0 al 9 (-1 para salir):\n"); while (scanf("%d", &num) == 1 && num != -1) { if (num >= 0 && num <= 9) { frecuencia[num]++; // ¡Seguro porque empezó en 0! } } printf("\nFrecuencia de cada dígito:\n"); for (int i = 0; i < 10; i++) { printf("Dígito %d: %d veces\n", i, frecuencia[i]); } free(frecuencia); frecuencia = NULL; return 0; }

13 Resumen del Cuarteto de Memoria Dinámica

1. malloc(bytes)

Reserva memoria rápida en el Heap sin inicializar (deja basura).

2. calloc(num, size)

Reserva memoria y pone cada byte en 0x00 (ideal para contadores).

3. realloc(ptr, new_size)

Agranda o reduce bloques preservando los datos. Usar siempre con puntero auxiliar temp.

4. free(ptr)

Devuelve la memoria al sistema operativo. Luego hacer ptr = NULL;.
