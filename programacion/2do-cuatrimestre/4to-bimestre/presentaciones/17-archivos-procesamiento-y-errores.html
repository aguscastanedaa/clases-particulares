01 Hoja de Ruta: Programas Que No Se Rompen

Lo que ya sabemos

  • Abrir, leer y escribir archivos con with open().
  • Modos r, w, a; write, read, recorrer líneas.
  • split(), strip(), int() y float() para convertir datos.
  • Los errores detienen el programa: ValueError, FileNotFoundError...

Lo que vamos a aprender

  • Capturar errores con try / except (y else, finally).
  • Validar datos del usuario sin que el programa se rompa.
  • Manejar archivos inexistentes.
  • Guardar y leer registros (nombre,nota,...).
  • Buscar, filtrar, actualizar y eliminar datos de un archivo.

🎯 Meta: que tus programas no se caigan ante un dato inválido o un archivo faltante, y que puedas mantener datos persistentes (agregar, consultar, modificar, borrar).

02 Repaso: Los Errores Detienen el Programa

Hasta ahora, cuando algo salía mal, Python mostraba un mensaje en rojo y terminaba el programa:

programa_fragil.pySe rompe
edad = int(input("Edad: ")) print("Dentro de un año tendrás", edad + 1) print("Fin del programa")
Salida en consola● ● ●
Edad: dieciocho Traceback (most recent call last): File "ejemplo.py", line 1, in <module> edad = int(input("Edad: ")) ValueError: invalid literal for int() with base 10: 'dieciocho'

Excepción

Un error que ocurre durante la ejecución se llama excepción. Si nadie la captura, el programa se interrumpe en esa línea (las siguientes no se ejecutan).

La solución

Python permite anticipar que algo puede fallar y decidir qué hacer si pasa, con la estructura try / except.

03 try / except: Sintaxis

try: # código que puede fallar
sintaxis_try.pyPlantilla
try: instrucciones_que_pueden_fallar except TipoDeError: que_hacer_si_falla resto_del_programa
1
try: → "intentá". El bloque indentado contiene el código que puede fallar.
2
except TipoDeError: → "si ocurre este error". Su bloque solo se ejecuta si hubo una excepción de ese tipo.
3
Si no hay error, el except se saltea. Si lo hay, el programa no se detiene: ejecuta el except y sigue con lo que viene después.

Dos caminos

  • Dato válido → se ejecuta todo el try y el except se ignora.
  • Dato inválido → falla int(...), se salta el resto del try (no se imprime lo de edad + 1) y se ejecuta el except. En ambos casos el programa llega al final.

Clave

Un try debe contener solo el código que puede fallar (no todo el programa), para saber exactamente qué error se está atrapando.

else

Se ejecuta solo si el try terminó sin errores: separa lo que puede fallar de lo que se hace si salió bien.

finally

Se ejecuta siempre, haya error o no (sirve para limpiar o avisar). Es opcional.

09 Pedir un Número Hasta que Sea Válido

pedir_entero.pyPython
def pedir_entero(mensaje): while True: try: return int(input(mensaje)) except ValueError: print(" Valor inválido. Probá de nuevo.") edad = pedir_entero("Edad: ") print("Edad registrada:", edad)
Salida en consola● ● ●
Edad: abc Valor inválido. Probá de nuevo. Edad: 3.5 Valor inválido. Probá de nuevo. Edad: Valor inválido. Probá de nuevo. Edad: 25 Edad registrada: 25

Cómo funciona

while True repite hasta que int(...) funcione. Cuando funciona, return devuelve el número y termina la función (sale del bucle). Si falla, el except avisa y el bucle vuelve a pedir.

Mejora a isdigit()

Este método sí acepta negativos y cualquier entero válido ("-5"), cosa que isdigit() no hacía (unidad 12). Es la forma más robusta.

10 Archivos: Manejar FileNotFoundError

archivo_no_existe.pyPython
try: with open("inexistente.txt", "r") as archivo: contenido = archivo.read() print(contenido) except FileNotFoundError: print("El archivo no existe") print("El programa sigue funcionando")
Salida en consola● ● ●
El archivo no existe El programa sigue funcionando

Sin try

El programa se detiene con FileNotFoundError y el usuario ve un mensaje técnico.

Con try / except

El programa muestra un mensaje claro y continúa (o pide otro nombre de archivo).

Comparación con C

En C se comprobaba if (archivo == NULL) después de fopen. En Python se atrapa la excepción: el código "feliz" queda limpio y el manejo de errores aparte.

13 Provocar Errores a Propósito: raise

Idea

Una función puede avisar que recibió un dato inválido "lanzando" una excepción con raise. Es la forma de exigir que se cumplan ciertas reglas.

raise.pyPython
def calcular_promedio(notas): if len(notas) == 0: raise ValueError("La lista de notas está vacía") return sum(notas) / len(notas) try: print(calcular_promedio([8, 6, 10])) print(calcular_promedio([])) except ValueError as error: print("Error:", error)
Salida en consola● ● ●
8.0 Error: La lista de notas está vacía

Quién decide qué hacer

La función detecta el problema (raise); quien la llama decide cómo reaccionar (try/except). Es mejor que devolver -1 o None cuando el valor inválido no debería pasar nunca.

20 Actualizar un Archivo: Leer → Modificar en Memoria → Reescribir

Idea fundamental

Un archivo de texto no se edita "en el lugar". El patrón estándar es: 1) leer todo a una lista, 2) modificar la lista, 3) volver a escribir todo el archivo con "w".

1. Leer
cargar() → lista
→
2. Modificar
Cambiar la lista
→
3. Reescribir
guardar() con "w"

Por qué no se modifica directamente

Cada línea tiene largo variable: cambiar 6.0 por 7.5 desplazaría todo lo que sigue. Es más simple y seguro reescribir el archivo completo desde la lista.

22 Eliminar un Registro

Mismo patrón

Cargar → construir una lista nueva sin el registro (filtrando con !=) → guardar. Con una comprensión: nuevos = [a for a in alumnos if a[0] != "Luis"].

eliminar.pyCon las funciones cargar() y guardar()
alumnos = cargar("alumnos.csv") nuevos = [a for a in alumnos if a[0] != "Luis"] guardar("alumnos.csv", nuevos)

Resultado

El archivo queda sin la línea de Luis. (Se usan las funciones cargar y guardar definidas antes en el mismo programa.)

25 Proyecto: Gestor de Notas (1/2) — Las Funciones de Persistencia

gestor_notas.pyParte 1: cargar y guardar
def cargar(): alumnos = [] try: with open("notas.csv", "r") as f: for linea in f: n, nota = linea.strip().split(",") alumnos.append([n, float(nota)]) except FileNotFoundError: pass return alumnos def guardar(alumnos): with open("notas.csv", "w") as f: for n, nota in alumnos: f.write(f"{n},{nota}\n")

cargar()

Lee notas.csv y devuelve una lista de listas [nombre, nota]. Si el archivo no existe (primera ejecución), el except FileNotFoundError hace que devuelva la lista vacía: el programa no se rompe.

guardar(alumnos)

Reescribe todo el archivo ("w") con el contenido actual de la lista, una línea nombre,nota por alumno. Es el patrón leer → cambiar en memoria → reescribir.

27 Error Frecuente #1: except Demasiado General

❌ Ocultar todos los errores
except_vacio.pyPeligroso
try: numero = int(input("Número: ")) print(10 / numero) except: pass
✅ Capturar solo lo esperado
except_especifico.pyClaro
try: numero = int(input("Número: ")) print(10 / numero) except ValueError: print("Escribí un número entero") except ZeroDivisionError: print("No se divide por cero")

Por qué

except: (o except Exception:) con pass traga cualquier error, incluso errores de programación (un nombre mal escrito). El programa falla en silencio y es muy difícil de depurar.

Regla

Atrapá los tipos concretos que esperás y decidí qué hacer con cada uno. Nunca dejes un except vacío.

30 Buenas Prácticas en Manejo de Errores y Archivos

Hacé

  • Capturá excepciones específicas.
  • Poné en el try solo lo que puede fallar.
  • Validá los datos del usuario (try/except + bucle).
  • Usá with para abrir archivos.
  • Mostrá mensajes útiles al usuario.
  • Para modificar datos: leer → cambiar en memoria → reescribir.

Evitá

  • except: vacío o con pass.
  • Imprimir el error técnico sin explicar al usuario.
  • Abrir con "w" un archivo que querés leer o conservar.
  • Asumir que los datos del archivo son válidos.
  • Mezclar lógica del programa y manejo de archivos en la misma función.
